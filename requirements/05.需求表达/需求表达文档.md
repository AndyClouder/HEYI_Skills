# 学员案例库系统 - 需求表达

## 1. 案例状态机图

### 状态定义
- **草稿** - 用户正在编辑或保存的案例
- **待审核** - 已提交等待导师审核
- **审核通过** - 导师审核通过，待安全检测
- **审核驳回** - 导师审核驳回，需用户修改
- **已发布** - 审核通过且安全检测通过，公开展示
- **已下架** - 管理员强制下架或作者主动下架

### PlantUML 状态图

```plantuml
@startuml
title 案例状态机图

state "草稿" as Draft {
    --> 待审核 : 用户提交审核
}

state "待审核" as Pending {
    --> 审核通过 : 导师审核通过
    --> 审核驳回 : 导师审核驳回
    --> 草稿 : 用户撤回提交
}

state "审核通过" as Approved {
    --> 已发布 : 安全校验通过
}

state "审核驳回" as Rejected {
    --> 草稿 : 用户修改后重新提交
    --> 待审核 : 用户修改后重新提交
}

state "已发布" as Published {
    --> 已下架 : 管理员强制下架
    --> 已下架 : 作者申请下架
    --> 已发布 : 管理员恢复
}

state "已下架" as Removed {
    --> 已发布 : 管理员恢复上架
    --> 草稿 : 作者重新编辑后提交
}

note right of Draft
  可编辑、可删除
  用户可见仅自己
end note

note right of Pending
  不可编辑
  等待审核
end note

note right of Published
  公开可见
  可下载、收藏、点赞
end note

note right of Removed
  不公开显示
  作者可见
end note

@enduml
```

## 2. 审核决策矩阵

### 状态维度分析

| 维度 | 状态 |
|------|------|
| 核心流程状态 | 草稿、待审核、已发布、已下架 |
| 审核子状态 | 等待分配、审核中、已完成 |
| 数据状态 | 信息完整、信息不完整、敏感词触发 |
| 时间状态 | 正常、即将超时（48小时）、已超时（72小时） |

### 导师/管理员审核决策矩阵

| 操作/状态 | 草稿 | 待审核 | 已发布 | 已下架 |
|:---|:---|:---|:---|:---|
| 查看详情 | ✅ | ✅ | ✅ | ✅ |
| 下载技能包 | ✅ | ✅ | ✅ | ✅ |
| 审核通过 | - | ✅ | - | - |
| 审核驳回 | - | ✅ | - | - |
| 强制下架 | - | ✅ | ✅ | - |
| 恢复上架 | - | - | - | ✅ |
| 编辑案例 | ✅(作者) | ❌ | ❌ | ❌ |
| 删除案例 | ✅(作者) | ❌ | ❌ | ✅(管理员) |

**条件说明：**
- (1) 仅作者本人可编辑草稿状态案例
- (2) 已发布案例需强制下架后才能编辑
- (3) 已下架案例作者可重新编辑后提交

## 3. 上传校验矩阵

### 前端校验（实时）

| 字段 | 校验规则 | 错误提示 |
|:---|:---|:---|
| 案例标题 | 必填，2-100字符 | 请输入案例标题（2-100字符） |
| 案例描述 | 必填，10-2000字符 | 请输入案例描述（至少10个字符） |
| 分类标签 | 必选1-5个 | 请至少选择1个标签 |
| 技能包格式 | 必选 | 请选择技能包格式 |
| 封面图片 | 可选 | 支持 JPG、PNG、WEBP，最大5MB |
| 技能包文件 | 必填，ZIP格式，1-100MB | 请上传ZIP格式技能包（最大100MB） |
| 版权声明 | 必须勾选 | 请确认版权声明 |

### 后端校验（提交时）

| 校验项 | 校验规则 | 错误代码 |
|:---|:---|:---|
| 用户权限 | 用户已登录 | ERR_NOT_LOGIN |
| 重复提交 | 同一用户24小时内未提交相同案例 | ERR_DUPLICATE_SUBMIT |
| 上传配额 | 每用户每天最多上传5个案例 | ERR_DAILY_LIMIT |
| 敏感词检测 | 内容不包含敏感词汇 | ERR_SENSITIVE_WORD |
| 文件结构 | 必须包含SKILL.md和references/目录 | ERR_INVALID_STRUCTURE |
| 代码安全扫描 | 不包含恶意代码 | ERR_MALICIOUS_CODE |

## 5. 编号规则

### 编号规则定义

| 编号部分 | 定义 | 示例 | 备注 |
|:---|:---|:---|:---|
| 类别标识 | 业务对象类型 | CASE- (案例)、USER- (用户)、TAG- (标签) | 大写字母+连字符 |
| 子类别 | 业务子类型 | UP (上传)、REV (审核)、BRO (浏览) | 大写字母缩写 |
| 序号 | 4位数字顺序号 | 0001, 0002... | 从0001开始 |
| 日期 | 可选，创建日期 | 20240408 | YYYYMMDD格式 |

### 编号规格
```
{类别标识}-{子类别}-{序号}[{-日期}]
```

### 示例编号

| 编号 | 含义 |
|:---|:---|
| CASE-UP-0001 | 案例上传-第1个案例 |
| CASE-REV-0002 | 案例审核-第2个案例 |
| CASE-BRO-0001 | 案例浏览-第1个案例 |
| USER-REG-0001 | 用户注册-第1个用户 |
| TAG-CAT-0001 | 分类标签-第1个标签 |
